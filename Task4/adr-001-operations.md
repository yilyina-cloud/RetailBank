# ADR-001. Ограниченный пилот приоритизации операций

Статус: предварительное — рекомендация к согласованию  
Версия: 1.0  
Дата: 17.11.2026  
Инициатива: №1, выявление подозрительных операций

## Контекст

Правила и внешние сигналы помечают около 35 тысяч операций в месяц. Финмониторинг проверяет около 10 тысяч. Нужно улучшить отбор без отмены обязательного контроля.

Разметки «схема / не схема» нет. Эскалация и исход расследования имеют разный смысл; непроверенная операция не считается безопасной.

## Жёсткие ограничения

- Модель не проводит и не блокирует платежи.
- Обязательные проверки и сроки имеют приоритет над score.
- Признаки должны быть доступны на момент оценки, без будущих исходов.
- Реальные данные используются только в согласованном контуре и по разрешённой цели.
- Решения по операциям остаются у финмониторинга.
- Отказ ML не должен останавливать существующий процесс.

## Критерии выбора

После проверки ограничений сравниваем варианты:

| Критерий | Вес |
|---|---:|
| Результативность при одинаковых экспертных часах | 40% |
| Полная стоимость | 25% |
| Надёжность, диагностика и откат | 20% |
| Срок и сложность внедрения | 15% |

Веса предложены для согласования. Баллы не выставлены: испытания ещё не проведены.

## Альтернативы

| Вариант | За | Против | Решение |
|---|---|---|---|
| Действующие правила и порядок по сумме | Уже работают, понятный baseline | Проверяется только часть очереди | Сохраняем как контроль и резерв |
| Isolation Forest внутри банка | Работает без меток схем, CPU, нет внешней передачи | Нетипичность не равна нарушению | Первый кандидат пилота |
| LOF в режиме novelty detection | Учитывает локальные отклонения | Требует проверки масштабируемости и устойчивости | Кандидат для сравнения |
| Обучаемый классификатор схем | Можно оптимизировать под подтверждённый исход | Недостаточно надёжных меток | Отложен |
| LLM или внешний API для скоринга | Доступны готовые модели | Не доказано преимущество для табличной задачи, добавляется передача данных | Не выбран |
| Та же модель в согласованном облаке | Альтернатива при нехватке внутренних ресурсов | Нужны согласования, сеть и полная смета | Резервный вариант размещения |

## Решение для пилота

Рекомендуется ограниченный пилот Isolation Forest внутри банка с сопоставлением с LOF и действующим процессом.

Модель оценивает только уже помеченные операции. Контрольная выборка из всего потока используется для исследования пропусков; расширение автоматического отбора на весь поток требует отдельного решения.

Архитектура: признаки → оценка нетипичности → проверка контракта → правила очереди → человек.

Нет истории, непригодные признаки или ошибка сервиса — возвращаем прежний порядок. Низкая оценка модели не снимает обязательную проверку.

## Решение для промышленной эксплуатации

Промышленный запуск пока не согласован.

Он возможен после подтверждения:
- качества на независимой выборке и критичных сегментах;
- выполнимости сроков и ручной нагрузки;
- готовности инфраструктуры и отката;
- допустимости обработки данных;
- экономического эффекта на горизонте 24 месяцев.

Начальное размещение внутри банка сохраняется, если нагрузочный тест и внутренняя смета его подтверждают. Иначе заново сравниваем согласованное облако и внутреннее расширение.

## Экономика

Дополнительная стоимость:
- запуск и 12 месяцев работы — 4,812 млн ₽;
- запуск и 24 месяца — 7,224 млн ₽.

С учётом существующего ФОТ ручного контура — 49,812 и 97,224 млн ₽ соответственно.

Окупаемость не доказана. Сценарий сокращения проверки на две минуты и денежной реализации половины свободного времени даёт 7,5 млн ₽ за два полных года. Запас относительно затрат мал.

Ценность дополнительных находок, снижение жалоб и регуляторного риска пока не монетизированы.

## Критичные допущения

| Допущение | Источник | Проверка |
|---|---|---|
| Нетипичность помогает выбрать полезные кейсы | Гипотеза Task2 | Сравнение с baseline |
| Эксперты согласованно оценивают результаты | План разметки | Повторная оценка и разбор расхождений |
| В банке доступны CPU и поддержка | Архитектурное допущение | Нагрузочный тест и подтверждение эксплуатации |
| Время проверки можно сократить | Экономический сценарий | Замер полного времени |
| Свободное время можно превратить в денежный эффект | Экономический сценарий | План финансов и владельца процесса |

## Риски

- Смещение исторической выборки: отдельный случайный контроль и сохранение вероятностей отбора.
- Новые сегменты: отказ от оценки до проверки применимости, отдельные срезы.
- Слепое доверие score: факты рядом с оценкой, выборочный аудит решений.
- Перегрузка экспертов: K по доступным часам, сроки важнее ранга.
- Подмена модели или данных: закрытый реестр, версии, контроль выпуска.
- Завышенный эффект: эскалации не считаются предотвращённым ущербом.

## План выхода

При отказе модели сохраняем действующие правила и рабочее место. ML-приоритет выключается конфигурацией.

Данные, признаки, наборы проверки и версии хранятся в банке. Модель подключена через версионированный контракт, поэтому её замена не требует изменения основного процесса.

Предусмотрен резерв 240 тыс. ₽ на замену или миграцию. Восстановление предыдущей версии проверяется до пилота.

## Триггеры пересмотра

- Ухудшение качества, новые сегменты или изменение правил контроля.
- Изменение источников данных, признаков или модели.
- Нехватка инфраструктуры либо превышение бюджета.
- Появление достаточных меток для классификации.
- Изменение требований к обработке данных.
- Отсутствие экономического эффекта после пилота.
