# Контроли, фолбэк и мониторинг

Числовые пороги ниже — стартовые предложения. До пилота их согласуют владельцы процессов. Изменения порогов версионируются.

## Автоматизация

| Сценарий | Действие системы | Кто принимает решение | Кто принимает риск режима |
|---|---|---|---|
| №1: пригодные данные | Меняет порядок необязательной части очереди | Финмониторинг решает по операции | Руководитель финмониторинга |
| №1: обязательная проверка | Сохраняет приоритет и срок независимо от score | Финмониторинг | Руководитель финмониторинга |
| №1: нет пригодной оценки | Сохраняет прежние правила и порядок | Финмониторинг | Руководитель финмониторинга |
| №18: извлечён показатель | Предлагает значение рядом с источником | Андеррайтер подтверждает критичные поля | Владелец кредитного процесса |
| №18: конфликт или нет источника | Не подставляет значение, передаёт на ручной разбор | Андеррайтер | Владелец кредитного процесса |
| №5: допущенная тема и достаточная уверенность | Назначает отдел | Система по согласованным правилам | Руководитель поддержки |
| №5: неоднозначное обращение | Передаёт диспетчеру | Диспетчер | Руководитель поддержки |

Автоблокировка, автоодобрение платежа и автоматическое кредитное решение в эти инициативы не входят.

## Фолбэк флагмана

| Наблюдаемый признак | Реакция |
|---|---|
| Нет обязательных признаков или снимок старше 30 минут | `not_scored`, прежний порядок |
| Новый сегмент, недостаточная история, значения вне области применимости | Прежний порядок; отдельная выборка для исследования |
| Низкий score при обязательном сигнале правила | Выполнить правило |
| Близкие оценки около границы top-K | Разрешить равенство по сроку, возрасту и прежним правилам |
| Невалидный ответ, неизвестная версия | Не применять результат, записать ошибку |
| Модель недоступна после повторов | Прежний порядок; уведомить дежурного |
| Рабочее место не принимает обновление | Сохранить событие для повтора; действующая очередь остаётся доступной |

Зона близких оценок определяется на validation-наборе. Она не означает «неуверенность в законности операции».

Фолбэк не создаёт дополнительную обязательную проверку для каждого сбоя: он возвращает кейс в существующий процесс. Иначе отказ модели перегрузит людей.

## Мониторинг флагмана

| Сигнал | Порог | Реакция | Ответственный |
|---|---|---|---|
| Потери или дубли операций | Любой подтверждённый случай | Остановить публикацию, сверить источник и очередь | Команда данных |
| Отсутствующие или устаревшие признаки | Более 5% заданий за 30 минут | Отключить ML для затронутого потока, восстановить витрину | Команда данных |
| Ошибки модели | Более 5% за 15 минут или 3 сбоя подряд | Переключить на прежний порядок | Дежурный инженер |
| Нарушение контракта | Любой случай | Отклонить ответ; при повторении откатить версию | Команда сервиса |
| Изменение распределения признаков | PSI > 0,2 по ключевому признаку два дня подряд | Проверить сегменты и качество; дрейф сам по себе не доказывает деградацию | ML-команда |
| Очередь экспертов | Прогноз нарушения согласованного срока хотя бы для обязательного кейса | Повысить приоритет, уведомить руководителя смены | Финмониторинг |
| Результативность top-K | Два недельных окна ниже сопоставимого baseline | Разобрать причины; при подтверждённом ухудшении вернуть baseline | ML + финмониторинг |
| Время разбора | Среднее выросло более чем на 10% против контроля | Проверить интерфейс и нагрузку; приостановить расширение | Финмониторинг |
| Лишние приостановки или жалобы | Рост более чем на 10% на сопоставимое число кейсов | Проверить связь с пилотом; при подтверждении остановить его | Комплаенс |
| Утечка, доступ не по роли, изменение платежа сервисом | Любой подтверждённый случай | Немедленно изолировать сервис | ИБ + дежурный |
| Расходы | Более 120% месячного бюджета | Проверить объём, повторы и ресурсы; пересчитать TCO | Владелец сервиса |

Результативность, время и жалобы смотрим по сегментам и с учётом размера выборки. Одиночное колебание редкой метрики не выдаём за доказанную деградацию.

Сроки обязательных проверок берутся из действующих правил банка. Их значения и владельцев нужно получить до пилота.

## Мониторинг дополнительных инициатив

| Инициатива | Сигнал | Реакция и владелец |
|---|---|---|
| №18 | Любое критичное значение без источника | Отклонить результат; приостановить новую версию, команда извлечения |
| №18 | Точность ниже 98% или полнота ниже 95% на контрольном наборе | Не выпускать версию; раздельно проверить OCR, модель и валидатор, ML + андеррайтинг |
| №18 | Более 5% технических ошибок за 15 минут | Ручной разбор, дежурный |
| №5 | Точность автоматического назначения ниже 95% по теме | Отключить автоматизацию этой темы, владелец поддержки |
| №5 | Покрытие ниже 50% | Пересмотреть эффект; не снижать порог ради охвата, ML |
| №5 | Рост переназначений или задержек срочных обращений | Вернуть прежний маршрут, руководитель поддержки |

Для обеих инициатив контролируем возраст ручной очереди. При угрозе согласованному сроку уведомляется руководитель смены.

## Безопасность по границам схем

| Граница | Угроза | Контроль |
|---|---|---|
| 1: вход в сервис операций | Неполные данные, подмена, лишний доступ к счетам | Служебная аутентификация, чтение разрешённых полей, сверка количества и ID, запрет изменения платежей |
| 2: исполнение модели | Ошибочный ответ, выход модели за полномочия | Изолированная среда без произвольного сетевого доступа; проверка контракта до изменения очереди |
| 3: публикация артефактов | Подмена весов, зависимостей или обучающего набора | Закрытый реестр, контрольные суммы, проверка лицензий и зависимостей, согласование выпуска, версия датасета |
| 4: клиентские документы | Вредоносный файл, инструкции внутри документа | Карантин, лимиты размера, проверка типа, изолированный парсер без макросов; текст документа считается данными |
| 5: провайдер модели | Утечка, сохранение данных, выдуманные поля | Минимизация контекста, согласованные регион и сроки хранения, запрет обучения на данных банка, контроль доступа поддержки, проверка источников ответа |
| 6: клиентский текст | Перегрузка, вредоносное содержимое в интерфейсе | Лимиты длины и частоты, нормализация, безопасное отображение текста |
| 7: классификатор | Произвольная тема или назначение несуществующего отдела | Закрытый список тем, проверка версии и оценки, назначение только через справочник |

Для всех сервисов: роли через банковский SSO, шифрование, секреты вне кода, минимальные журналы без полных документов и реквизитов. Сроки хранения и удаления согласуются с владельцем данных и ИБ.

## Проверка человеком и выпуск изменений

- Сотрудник видит исходные факты; score не подписывается как «вероятность нарушения».
- Исправления и исходы проверок сохраняются раздельно: эскалация, результат расследования, подтверждённый случай.
- Контроль качества включает случайную выборку и отдельную выборку рискованных случаев. Их результаты не смешиваются без весов.
- Новая версия проходит диагностические тесты, приёмочный набор, срезы старых и новых сегментов, затем теневой запуск.
- Версионируются признаки, модель, преобразование score, контракт и правила очереди; для №18 также OCR и промпт.
- Дежурный может сразу выключить ML-приоритизацию. Возврат в работу согласуют владелец процесса и технический владелец после проверки причины.
